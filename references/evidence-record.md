# Evidence Record Contract

Use one evidence directory for each real task iteration. The project chooses the evidence root; this repository defines the record shape but does not create fictional execution records.

## Identity

Choose a task identifier that is unique inside the project, for example:

`<date>-<short-task-name>-<iteration>`

Record:

- repository and source revision;
- initial worktree state;
- target MCU, board and revision;
- SDK, toolchain and host environment;
- selected workflow;
- confidentiality and redaction boundary.

## Suggested layout

```text
<project-evidence-root>/<task-id>/
├─ context.yaml          # Hardware and software facts, sources and unknowns
├─ task-contract.yaml    # Goal, non-goals, scope and acceptance criteria
├─ approvals.md          # Exact state-changing actions approved by the developer
├─ commands/
│  ├─ inspection.log     # Read-only discovery commands and output
│  └─ tests.log          # Host/static/tool checks and output
├─ build/
│  ├─ build.log          # Exact build output
│  ├─ artifacts.yaml     # Artifact path, size and hash from the current build
│  └─ map-or-size.txt    # Only when generated by the real build
├─ device/
│  ├─ program.log        # Erase/program/verify/reset output
│  ├─ serial.log         # Raw serial capture
│  ├─ debugger.log       # J-Link/GDB/OpenOCD evidence
│  └─ measurements.md    # Instrument, test point, setup and observation
└─ result.md             # Acceptance results, states, risks and next action
```

Create only files produced by the current task. Omit channels that did not run; do not add placeholder logs that could be mistaken for execution evidence.

## Command record

Every meaningful command record must include:

```yaml
command_record:
  stage: "inspection | test | build | flash | serial | debugger | hardware"
  purpose: "[TO BE PROVIDED]"
  working_directory: "[TO BE PROVIDED]"
  command: "[TO BE PROVIDED]"
  started_at: "[TO BE PROVIDED]"
  tool_versions: {}
  mutates_state: false
  approval_reference: "[TO BE PROVIDED when mutates_state is true]"
  result:
    exit_code: "[TO BE PROVIDED]"
    raw_output: "[TO BE PROVIDED]"
```

Do not reconstruct a command, exit code or output after the fact without marking it as developer recollection.

## Artifact identity

Before programming a device, record:

- source revision and worktree state;
- exact build target and configuration;
- build state;
- artifact path;
- artifact size;
- cryptographic hash produced from the artifact being programmed;
- intended MCU, board, address or partition.

The programmed artifact must be traceable to the recorded build. A filename or timestamp alone is insufficient when multiple builds may exist.

## Result states

For each acceptance criterion, use one task status:

- `Verified`
- `Implemented, not rerun`
- `Planned`
- `Illustrative`
- `Blocked`

Report exactly one build state:

- `BUILD PASSED`
- `BUILD FAILED`
- `BUILD NOT RUN`

Report exactly one hardware state:

- `HARDWARE PASSED`
- `HARDWARE FAILED`
- `HARDWARE NOT RUN`

A hardware-dependent acceptance criterion can be `Verified` only when the task has `HARDWARE PASSED` and the saved observation directly supports that criterion.

## Redaction

Keep original evidence inside its authorized project boundary. Before evidence leaves that boundary:

1. Copy only the minimum required excerpt.
2. Remove credentials, customer identifiers, production endpoints, unique device IDs, private protocols and confidential schematic details.
3. Preserve line numbers, timestamps or hashes needed to relate the excerpt to the original.
4. Record that redaction occurred.

Never replace the authorized original with the redacted copy.

## Final result

`result.md` must state:

- task scope and selected workflow;
- context sources and unresolved facts;
- changed paths;
- acceptance criterion status with evidence path;
- build state with command and artifact identity;
- hardware state with target and observation;
- skipped stages and reasons;
- remaining risks and smallest safe next action;
- verified rules eligible for context maintenance.
